# 갤럭시·아이폰·Google 캘린더 동기화 구조 조사

조사일: 2026-10-16. Android·Apple·Google 개발자 문서는 원문으로 확인했다. samsung.com·support.apple.com은 이 작업 환경에서 열리지 않아 검색 요약으로 확인했고 **[2차]**로 표시했다. 실기기에서 확인해야 할 항목은 **[실기기]**로 표시했다.

---

## 1. 한눈에 보는 구조

```text
 갤럭시                                   아이폰
 ┌─────────────────────────────┐          ┌─────────────────────────────┐
 │ 삼성 캘린더    OLO Calendar  │          │ 아이폰 캘린더  OLO Calendar │
 │        \        /            │          │        \        /           │
 │  Calendar Provider (SQLite)  │          │   EventKit 저장소           │
 │  CalendarContract 테이블     │          │   EKEventStore              │
 │        │                     │          │        │                    │
 │  Google 동기화 어댑터        │          │  CalDAV 계정(Google)        │
 │  (계정 유형 com.google)      │          │  Fetch 주기로 가져옴        │
 └────────┼─────────────────────┘          └────────┼────────────────────┘
          │  Google 내부 프로토콜                    │  CalDAV (WebDAV + iCalendar)
          └──────────────►  Google 캘린더  ◄─────────┘
                         (원본 · REST API / CalDAV / ICS)
```

- 원본은 Google 캘린더 하나다.
- 각 휴대폰은 OS가 자기 저장소와 Google을 동기화한다. 기본 캘린더 앱과 OLO는 **같은 저장소를 공유**하므로 같은 기기 안에서는 바로 같은 내용을 본다.
- 기기 사이의 반영은 OS 동기화 주기에 달려 있다. 갤럭시는 Google 동기화 어댑터, 아이폰은 Fetch 주기를 따른다.

## 2. 각자가 쓰는 "언어"

| 구간 | 데이터 형식 / 프로토콜 | 반복 규칙 표현 | 비고 |
|------|------------------------|----------------|------|
| 공통어 | **iCalendar (RFC 5545)**: VEVENT, UID, DTSTART, RRULE, EXDATE, VALARM | `RRULE:FREQ=WEEKLY;BYDAY=MO` | 세 시스템 모두 이 개념을 바탕으로 함 |
| Google 캘린더 | REST API v3 (JSON), CalDAV, ICS 구독 주소(읽기 전용) | `recurrence[]`에 RRULE/EXRULE/RDATE/EXDATE 문자열 | 색·라벨·첨부·이벤트 유형은 REST API에서만 다룸 |
| 갤럭시(Android) | `CalendarContract` 테이블(Calendars, Events, Instances, Reminders, Attendees, Colors) | `Events.RRULE` 컬럼에 RFC 5545 문자열 | 삼성 캘린더 앱은 Kotlin/Java 앱 |
| 아이폰(iOS) | EventKit 객체(EKCalendar, EKEvent, EKRecurrenceRule, EKAlarm) | `EKRecurrenceRule` 객체. 일·주·월·년만 되고 일정당 규칙 1개 | 내부에서 CalDAV로 Google과 통신 |
| OLO Calendar | Kotlin(공용 로직·화면) + Swift(아이폰 위젯) | 공통 모델 → 각 OS 형식으로 변환 | 1단계에서는 OLO가 일정 데이터를 따로 저장하지 않음 |

## 3. 시스템별 핵심 사실

### 3.1 Google 캘린더
| 항목 | 내용 | 출처 |
|------|------|------|
| 일정 ID | `id`는 회차마다 다르고 `iCalUID`는 반복 전체가 같다. 예외 회차는 `recurringEventId` + `originalStartTime`으로 식별 | [Events](https://developers.google.com/workspace/calendar/api/v3/reference/events) |
| 종일 일정 | `start.date`(yyyy-mm-dd). 시간 일정은 `dateTime` + `timeZone`. 반복 일정은 timeZone 필수 | 같은 문서 |
| 알림 | popup/email, 최대 5개. 사용자별 값. **이메일 알림은 아이폰에서 동작하지 않음** | 같은 문서, [iOS 동기화](https://support.google.com/calendar/answer/99358?co=GENIE.Platform%3DiOS&hl=en) |
| 색 | 캘린더 색(사용자별)과 일정 색(colorId 1–11). 새로 나온 **Labels**(캘린더당 최대 200개)가 colorId를 대체하는 중 | [Colors](https://developers.google.com/workspace/calendar/api/v3/reference/colors), [Labels](https://developers.google.com/workspace/calendar/api/guides/labels) |
| CalDAV | HTTPS + OAuth만 허용. 캘린더 생성(MKCALENDAR), 할 일(VTODO), 소리 알람 미지원. 일정 색·첨부·이벤트 유형은 다루지 않음 | [CalDAV 가이드](https://developers.google.com/workspace/calendar/caldav/v2/guide) |
| 충돌 | REST·CalDAV 모두 If-Match(etag)를 지원한다. 조건 없이 쓰면 마지막에 쓴 쪽이 이김 | [버전 관리](https://developers.google.com/workspace/calendar/api/guides/version-resources) |
| 공휴일 | "대한민국의 휴일"은 읽기 전용 구독 캘린더. ID는 `…#holiday@group.v.calendar.google.com` 형태 | [공휴일](https://support.google.com/calendar/answer/13748345?hl=en) |
| 음력 | 웹의 "대체 캘린더"는 화면 표시 옵션일 뿐이고, 데이터로 넘어오지 않음. **RRULE로는 음력 반복을 표현할 수 없음** | [대체 캘린더](https://support.google.com/calendar/answer/13748650?hl=en) |

### 3.2 갤럭시: Android Calendar Provider + 삼성 캘린더
| 항목 | 내용 | 출처 |
|------|------|------|
| 저장소 | `CalendarContract`. 화면 표시는 반복을 펼친 `Instances` 테이블(읽기 전용, 기간 지정 필수)을 씀 | [Calendar Provider](https://developer.android.com/identity/providers/calendar-provider) |
| 일정 넣기 | 필수값은 dtstart, eventTimezone, calendar_id. 단일 일정은 dtend, 반복 일정은 **duration + rrule** | [Events](https://developer.android.com/reference/android/provider/CalendarContract.Events) |
| 종일 일정 | **eventTimezone = "UTC", 시각은 UTC 자정**. 어기면 하루씩 밀림 | 같은 문서 |
| 예외 회차 | `Events.CONTENT_EXCEPTION_URI/{원본 ID}`에 `ORIGINAL_INSTANCE_TIME`을 넣어 만듦. 예외는 다시 반복할 수 없음 | 같은 문서 |
| 동기화 표시 | 앱이 고치면 `DIRTY=1`. 어댑터가 Google에 올리면 0이 되고 `_SYNC_ID`(Google 일정 ID)가 채워짐. 앱이 삭제하면 `DELETED=1`로 표시만 됨 | [SyncColumns](https://developer.android.com/reference/android/provider/CalendarContract.SyncColumns) |
| 일정 색 | `EVENT_COLOR_KEY`는 그 계정의 Colors 테이블에 있는 키만 쓸 수 있음. 임의 RGB는 Google로 올라가지 않음 | [Colors](https://developer.android.com/reference/android/provider/CalendarContract.Colors) |
| 계정 구분 | `ACCOUNT_TYPE`: `com.google`이면 Google 동기화, `LOCAL`이면 기기 전용. 삼성 계정·Exchange 등은 각자 고유 유형 | [CalendarContract](https://developer.android.com/reference/android/provider/CalendarContract) |
| 권한 | `READ_CALENDAR` / `WRITE_CALENDAR`(런타임 권한) | [Calendar Provider](https://developer.android.com/identity/providers/calendar-provider) |
| 지금 동기화 | `ContentResolver.requestSync(계정, "com.android.calendar", MANUAL+EXPEDITED)` | Android 표준 API |
| 변경 감지 | 앱이 열려 있을 때는 ContentObserver를 쓴다. `PROVIDER_CHANGED` 브로드캐스트는 Android 8 이후 매니페스트로 받을 수 없음 | [브로드캐스트 예외](https://developer.android.com/develop/background-work/background-tasks/broadcasts/broadcast-exceptions) |
| 삼성 전용 | 스티커, 리마인더 연동, 한국 음력 표시, 음력 반복은 Google로 넘어가지 않거나 불확실 **[2차][실기기]** | samsung.com 커뮤니티 |
| 공휴일 중복 | 삼성 자체 공휴일과 Google "대한민국의 휴일"을 함께 켜면 겹침 **[2차]** | samsung.com 커뮤니티 |
| 과거 일정 | Google 앱 기준으로 지난 일정은 1년치만 동기화 | [Android 동기화 문제](https://support.google.com/calendar/answer/6261951?co=GENIE.Platform%3DAndroid&hl=en) |

### 3.3 아이폰: EventKit + 아이폰 캘린더
| 항목 | 내용 | 출처 |
|------|------|------|
| 권한 | iOS 17부터 `requestFullAccessToEvents`. **읽기 전용 권한은 없고**, 쓰기 전용으로는 일정을 읽을 수 없음. `NSCalendarsFullAccessUsageDescription` 필수 | [저장소 접근](https://developer.apple.com/documentation/eventkit/accessing-the-event-store) |
| 식별자 | 여러 기기에서 같은 일정을 가리키는 것은 `calendarItemExternalIdentifier`. 로컬 ID는 전체 재동기화 때 바뀔 수 있음 | [externalIdentifier](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemexternalidentifier) |
| 색 | **캘린더 색만 있고 일정별 색은 없음** | [EKEvent](https://developer.apple.com/documentation/eventkit/ekevent) |
| 반복 | 일·주·월·년만 되고 일정당 규칙 1개. 편집 범위는 `.thisEvent` / `.futureEvents` | [EKRecurrenceRule](https://developer.apple.com/documentation/eventkit/ekrecurrencerule) |
| 참석자 | 읽기 전용. EventKit으로 초대를 보낼 수 없음 | [attendees](https://developer.apple.com/documentation/eventkit/ekcalendaritem/attendees) |
| 변경 감지 | `EKEventStoreChanged` 알림을 받으면 보이는 범위를 다시 읽음. iOS 26에는 타입이 지정된 메시지가 추가됨 | [EKEventStoreChanged](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/ekeventstorechanged) |
| Google 계정 | Push가 없고 Fetch(15분·30분·1시간·자동·수동)로만 가져옴 **[2차][실기기]** | Apple 커뮤니티 |
| 소스 구분 | iCloud도 `.calDAV`로 보여서, Google인지 구분하려면 source 이름 등 다른 단서가 필요 **[실기기]** | [EKSourceType](https://developer.apple.com/documentation/eventkit/eksourcetype) |
| 기본 캘린더 | 기본 캘린더가 iCloud면 새 일정이 Google로 가지 않음 | Google 지원 문서 |
| 음력 | iOS 26부터 `Calendar.Identifier.dangi`(한국 음력). `.chinese`는 한국 음력과 하루씩 어긋나는 달이 있음(예: 2026-10-10~11-08) | [dangi](https://developer.apple.com/documentation/foundation/calendar/identifier-swift.enum/dangi) |
| Kotlin 연동 | Kotlin/Native에 `platform.EventKit` 바인딩이 있음. 위젯(WidgetKit)은 Swift로만 만들 수 있음 | [EventKit.def](https://github.com/JetBrains/kotlin/blob/master/kotlin-native/platformLibs/src/platform/ios/EventKit.def) |

|------|-----------------|-----------------|----------|
| 제목·시간·종일·장소·메모 | 됨 | 됨 | 기본 지원 |

| 예외 회차(이번만 변경) | 됨 | 됨 | 기본 지원 |

| 삼성 스티커·리마인더 | 안 됨 | 해당 없음 | 건드리지 않음(필요한 컬럼만 수정) |
| 로컬/iCloud 캘린더 일정 | 동기화 안 됨 | 동기화 안 됨 | 저장 전에 경고 |

## 5. 동기화 지연과 충돌

- **같은 기기 안**: 저장소가 같아서 바로 반영된다.
- **갤럭시 → Google**: 어댑터가 DIRTY 일정을 올린다. 배터리 최적화·백그라운드 데이터 제한의 영향을 받는다 **[2차]**.
- **Google → 아이폰**: Fetch 주기(최소 15분, 또는 수동)를 따른다. 앱에서는 `refreshSourcesIfNecessary()`로 요청만 할 수 있다.
- **충돌**: 두 기기에서 같은 일정을 거의 동시에 고치면 OS 동기화 과정에서 대체로 나중에 올라간 쪽이 남는다 **[실기기]**. OLO는 고치기 직전에 저장소에서 다시 읽고, 바뀐 컬럼만 쓴다.

## 6. OLO에 주는 결론

1. 1단계의 OLO는 **OS 저장소만 읽고 쓰는 앱**이다. 서버, Google 로그인, 자체 일정 DB가 없다.
2. 분류는 **캘린더 색**으로 한다. 아이폰에 일정별 색이 없기 때문이다.
3. 반복 편집기는 **아이폰이 표현할 수 있는 범위**로 제한한다. 일·주·월·년, 간격, 요일, 종료(날짜/횟수)까지다.
4. 저장할 캘린더의 기본값은 **Google 캘린더**로 하고, 로컬·iCloud·삼성 계정 캘린더에 저장할 때는 경고한다.
5. 종일 일정은 Android에서 UTC 자정으로 저장한다.
6. 고칠 때는 **바뀐 컬럼만** 쓴다. 삼성 전용 정보를 지우지 않기 위해서다.
7. 동기화 상태를 보여 준다. 갤럭시는 업로드 대기(DIRTY) 건수와 계정 동기화 켜짐 여부, 아이폰은 마지막 새로고침 시각을 보여 준다.
8. 공휴일은 한 곳만 쓴다. Google 공휴일 캘린더를 찾아 빨간 글씨로 표시하고, 중복을 안내한다.
9. 음력은 3단계로 미룬다. 한국 음력 계산은 KASI 자료 기반 표가 필요하고 `.chinese`는 쓰지 않는다.
