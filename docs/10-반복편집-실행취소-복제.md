# 10. 반복 일정 범위 편집 · 삭제 실행 취소 · 일정 복제 (0.13.0)

근거: 다른 앱 비교(2026-10-19) 2순위 2·4번. 삼성 캘린더와 Google 캘린더는 반복 일정을 고치거나 지울 때 범위를 묻는다. OLO는 지금까지 "전체 수정"만 됐고, 편집기에 "다음 버전에서 지원"이라고 적혀 있었다(0.11.0에서 삭제).

## 1. 사용 흐름

| 동작 | 단일 일정 | 반복 일정의 한 회차 | 따로 바꾼 회차(예외) |
|---|---|---|---|
| 편집 | 바로 편집기 | **이 일정만 / 이 일정과 이후 일정 / 전체 반복 일정** 중 고른 뒤 편집기 | 이 회차만 편집 |
| 삭제 | "이 일정을 삭제할까요?" | 세 가지 범위 중 하나를 골라 삭제 | "반복 중 이 일정만 삭제할까요?" |
| 복제 | 같은 내용의 새 일정을 편집기로 연다 | 그 회차의 날짜로 반복 없는 새 일정 | 같음 |

- **편집기 안내 문구:**
  - 이 일정만: "반복 중 이 일정만 바뀝니다." 반복 항목과 캘린더 고르기는 숨긴다(회차는 원래 캘린더에 남는다).
  - 이후: "이 일정부터 이후 일정이 바뀝니다. 지난 일정은 그대로입니다."
  - 전체: "반복 일정 전체가 바뀝니다." 첫 회차 날짜로 연다(지금까지와 같음).
- **연동 안내:** 연동된 캘린더의 일정을 삭제할 때는 범위와 상관없이 "Google 메인 캘린더와 아이폰에서도 삭제됩니다"를 붙인다.

## 2. 저장 방식 (Android CalendarContract)

| 범위 | 편집 | 삭제 |
|---|---|---|
| 이 일정만 | `CONTENT_EXCEPTION_URI/{master}`에 예외 행을 넣는다(ORIGINAL_INSTANCE_TIME = 회차 시작). 알림은 예외 행에 따로 쓴다 | 같은 URI에 STATUS_CANCELED 예외를 넣는다. 이미 바뀐 회차는 행을 지우지 않고 취소 상태로 바꾼다(행을 지우면 원래 회차가 되살아난다) |
| 이후 | 원래 반복의 RRULE을 회차 직전 UNTIL로 끝낸다. 그 뒤에 있던 예외 행을 지우고, 편집 내용으로 새 반복을 만든다. "N회" 규칙은 앞서 지난 횟수를 빼서 이어 간다 | 원래 반복을 회차 직전에 끝낸다. 그 뒤의 예외 행도 지운다 |
| 전체 | 기존 저장과 같다 | 마스터 행을 삭제한다 |

- 고른 회차가 첫 회차면 "이후"는 "전체"와 같게 처리한다.
- **UNTIL 표기(RFC 5545):**
  - 시간 일정: UTC `yyyyMMddTHHmmssZ`. 값은 회차 시작 1초 전이다.
  - 종일 일정: 날짜 `yyyyMMdd`. 값은 회차 전날이다.
- **연동:**
  - 삼성 캘린더의 반복이 바뀌면 지문(규칙·예외 포함)이 달라진다. 그래서 다음 연동 때 Google 메인 캘린더 쪽 반복도 다시 맞춘다.
  - "이후" 편집으로 생긴 새 반복은 새 일정으로 복제된다.

## 3. 삭제 실행 취소

- 삭제를 누르면 일정이 화면에서 바로 사라진다. 아래에 "‘회의’를 삭제했습니다 (이 일정만) · **실행 취소**"가 5초 동안 보인다.
- **5초 동안은 휴대폰 캘린더에 아무것도 쓰지 않는다.** 그래서 실행 취소한 삭제는 삼성 캘린더, 연동, 아이폰 어디에도 흔적이 남지 않는다.
- **실제 삭제는 다음 셋 중 가장 먼저 오는 때에 한다.**
  - 5초가 지났을 때
  - 다른 삭제를 했을 때
  - OLO가 화면에서 내려갔을 때(ON_STOP). 화면 수명과 상관없는 별도 작업으로 보내므로, 앱을 바로 닫아도 삭제가 빠지지 않는다.
- 이 사이에 다시 읽어 와도 지울 일정은 화면에 다시 나타나지 않는다(`shownNow`).

## 4. 코드

- `model/SeriesEdit.kt`:
  - `EditScope`, `OccurrenceRef(covers, isException)`
  - `occurrenceDraft`: 반복 일정의 내용을 고른 회차의 날짜로 옮긴다.
  - `ruleEndingBefore`, `ruleCount`, `ruleWithCount`
- `store/CalendarStore.kt`: `saveOccurrence`, `deleteOccurrence`. 기본 구현은 전체 저장·삭제다(iOS와 테스트용).
- `AndroidCalendarStore`: 예외 행 삽입·취소, `endSeriesBefore`, `occurrencesBefore`.
- `CalendarController`:
  - `saveOccurrence`
  - `delete(o, scope)`, `undoDelete`, `flushPendingDelete`
  - `PendingDelete` 상태, `UNDO_MILLIS = 5000`
- 화면:
  - 상세 시트: 범위 선택 `ScopeChoices`, 편집 · 복제 · 삭제 버튼
  - `EventEditorSheet(scope)`
  - `UndoBar`
  - `App`의 ON_STOP 처리
- 테스트 `SeriesEditTest` 4건: UNTIL·COUNT 계산, 범위별 대상 회차, 회차 날짜로 열기, 삭제 대기·실행 취소·5초 뒤 실제 삭제.

## 5. 실기기 확인 필요

- 삼성 캘린더 계정과 Google 계정 각각에서 "이 일정만 편집"과 "이 일정만 삭제"가 삼성 캘린더 앱에 그대로 보이는지
- 연동 중인 반복 일정에서 범위 편집이 아이폰까지 맞게 가는지
- 실행 취소 직후 삼성 캘린더 앱에서 그 일정이 그대로인지
