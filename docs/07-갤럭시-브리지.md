# 갤럭시 브리지: Samsung Calendar ⇄ 구글 메인 계정 (0.8.0)

2026-10-17

## 1. 왜 필요한가
- 갤럭시 사용자는 일정을 **Samsung Calendar(삼성 계정)**에 저장합니다. 그래야 갤럭시 폰·탭·북이 삼성 클라우드로 같은 일정을 공유합니다.
- Samsung Calendar는 아이폰으로 가지 않습니다. 아이폰은 삼성 계정을 읽지 못합니다.
- 0.7.0까지의 "Google로 옮기기(원본 삭제)"는 원본을 지우므로 갤럭시 생태계를 깨뜨립니다. 그래서 **원본을 유지한 채 양방향으로 계속 맞추는 브리지**로 바꿉니다.

```
 갤럭시 생태계 (폰·탭·북)           구글 메인 계정 (허브)           애플 생태계
 Samsung Calendar ⇄ [OLO 브리지] ⇄        ●        ⇄ (iOS 기본 기능: CalDAV) ⇄ 아이폰·아이패드·맥
```

## 2. 결정 사항(사용자 승인)
- **담는 곳:** 구글 메인 계정의 기본 캘린더. 추가 로그인이 필요 없습니다.
- **충돌:** 양쪽이 동시에 바뀌면 Samsung 쪽을 남기고 횟수를 알립니다.
- **아이폰:** 구글 메인 계정을 직접 씁니다(iOS 기본 기능). iCloud 브리지는 나중에 넣습니다.

## 3. 동작
| 항목 | 구현 |
|---|---|
| 단위 | "시리즈". 단일 일정, 또는 반복 일정 + 그 예외 회차(변경·취소)를 하나로 봅니다. |
| 같음 판정 | 지문(fingerprint, FNV-64 해시): 제목·장소·메모·종일·시작·끝·시간대·반복 규칙(정규화: `WKST=MO` 제거, 항목 정렬)·제외 날짜·알림 분·예외 회차. 동기화 어댑터가 덧붙이는 관리용 값은 넣지 않습니다. 그래서 브리지가 쓴 내용이 메아리처럼 되돌아와도 아무 일도 일어나지 않습니다. |
| 짝 기록 | (Samsung id, 구글 id, 각 쪽 지문)을 OLO 설정(`bridge.links`)에 저장합니다. |
| 계획 | `planBridge()`(순수 함수)<br>· 지문이 다르고 한쪽만 바뀜 → 그쪽에서 다른 쪽으로 반영<br>· 둘 다 바뀜 → Samsung 우선, 충돌 횟수에 더함<br>· 한쪽이 사라짐 → 다른 쪽도 삭제<br>· 짝 없는 일정 → 제목·시작·종일이 같은 것끼리 먼저 짝을 짓고(첫 연결 때 중복 방지), 나머지는 복제 |
| 안전 정지 | 한 번에 지워질 시리즈가 max(5, 짝 수의 20%)를 넘으면 삭제를 보류하고 확인을 받습니다. 나머지 반영은 그대로 진행합니다. |
| 쓰기 | 복제: 원본 행을 복사하고(반복 규칙은 DURATION으로), 예외 회차는 `CONTENT_EXCEPTION_URI`에 진짜 예외로 넣습니다. 그래야 반대쪽에서 낱개 일정으로 되돌아오지 않습니다. 알림도 복사하고, 참석자는 복사하지 않습니다(초대 메일 방지).<br>갱신: 단일 일정은 같은 id를 유지한 채 바뀐 내용만 고칩니다. 그래서 아이폰에서도 같은 일정으로 남습니다. 반복이 얽힌 일정은 시리즈를 새로 만들고 짝을 다시 잇습니다. |
| 되읽기 | 쓴 뒤 양쪽을 다시 읽어, 실제 저장된 지문으로 짝 기록을 갱신합니다. 쓰기가 실패한 짝은 예전 지문을 유지하므로, 다음 번에 다시 시도합니다. |
| 실행 시점 | 앱이 켜져 있을 때: 저장소가 바뀌고 3초 뒤.<br>앱이 꺼져 있을 때: WorkManager<br>· 캘린더 저장소가 바뀌면 깨어나는 1회성 작업(5초 모아서, 최대 60초). 실행 뒤 다시 걸어 둡니다.<br>· 놓친 변경을 메우는 15분 주기 작업 |
| 화면 | 짝지어진 일정은 OLO에서 Samsung 쪽 하나만 보입니다. 변경 회차도 시리즈 id로 함께 숨깁니다.<br>서랍의 Samsung Calendar 줄: "구글 메인과 연결 ›" → 연결 후 "● 구글 메인 연결 · 맞춤 n분 전"<br>연결 화면: 구글 계정 선택, 첫 연결 미리보기(삼성→구글 n · 구글→삼성 n · 짝만 지음 n), 동기화가 꺼진 계정 바로 켜기, 지금 맞추기, 보류된 삭제 진행, 연결 해제(양쪽 일정은 그대로 둠) |

## 4. 한계와 주의
- **브리지 기기는 한 대:** 갤럭시 여러 대에서 브리지를 켜지 마세요. 짝 기록이 기기마다 따로 있습니다. 첫 연결의 "같은 일정 짝짓기"가 중복을 상당 부분 막지만 완전하지 않습니다.
- **삼성 캘린더 앱의 중복:** 삼성 캘린더 앱에서 구글 메인 캘린더 표시를 끄도록 연결 화면에서 안내합니다. 양방향 복제라서 빠지는 일정은 없습니다.
- **Samsung 전용 정보:** 스티커, 음력 반복 등은 Google에 담기지 않습니다. 반대 방향 갱신도 화면에 보이는 값만 덮어씁니다.
- **iOS 쪽 반영 속도:** 아이폰의 "데이터 가져오기" 주기를 따릅니다.
- **실기기 확인이 필요한 부분:** Samsung 계정 캘린더에 예외 회차를 넣는 동작, 삼성 클라우드가 동기화 중에 고치는 값이 지문을 흔드는지 여부. 흔든다면 정규화 항목을 추가합니다.

## 5. 테스트
`BridgeTest`(7개)
- 첫 연결: 짝짓기·복제가 양쪽으로 일어나고 중복이 없음
- 안정 상태: 할 일 없음
- 양방향 반영과 충돌 시 Samsung 우선
- 삭제 전파와 대량 삭제 보류
- 지문 정규화(규칙 순서, WKST, 제외 날짜 중복, 알림 순서)
- EXDATE 해석(Z·날짜만·TZID), 짝 기록 저장·복원
- 메모리 저장소로 엔진을 돌려 확인: 첫 실행 → 두 번째 실행에서 쓰기 0 → 구글 쪽 수정이 Samsung에 반영 → Samsung 삭제가 구글에 반영
