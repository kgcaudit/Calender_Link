# 09. 홈 화면 위젯 구상안 (0.12.0: W1, 0.12.1: W2 적용)

작성: 2026-10-19 · 근거: docs/02(권장 기능 "홈 화면 위젯"), 다른 앱 비교(대화 2026-10-19), Android 위젯 가이드

## 1. 목표

- 앱을 열지 않고도 **오늘·이번 주 일정**을 본다. 매일 쓰는 캘린더 앱의 주된 접점이다.
- OLO만의 강점인 **연동 상태**(삼성 캘린더 ↔ Google 메인 캘린더 ↔ 아이폰)를 홈 화면에서 확인한다.
  "아이폰에도 갔나?"를 앱을 열지 않고 안다.
- 삼성 캘린더 위젯과 나란히 두어도 어색하지 않은 OLO 디자인(Clay 강조색, 라이트/다크)을 쓴다.

## 2. 조사 요약

| 앱 | 위젯 | 시사점 |
|---|---|---|
| 삼성 캘린더 | 목록(다가오는 일정), 월, 할 일. 투명도 조절. 가장 작은 크기 3×3(One UI 4 이후) | 월 위젯에 다가오는 일정이 없다는 불만이 있다. 글자 크기를 조절할 수 없다 |
| Google 캘린더 | 일정(목록), 월, 1×1 날짜 | 목록 위젯이 가장 많이 쓰인다. 날짜 머리글을 고정해 스크롤한다 |
| 네이버·Business Calendar | 월+목록 복합, 주, D-day | 크기를 바꾸면 보이는 내용이 바뀌는 반응형 구성 |
| Android 가이드 | Android 12 이상은 크기별 반응형 레이아웃을 권장. 라이트/다크와 대비 설정을 따른다 | Glance의 `SizeMode.Responsive`로 크기마다 다른 구성을 만든다 |

## 3. 위젯 구성 (제안)

### W1. 일정 목록 — 1차 (기본 4×2, 크기 3×2 ~ 5×5)

```
┌──────────────────────────────────┐
│ 10월 19일 (월)            [+]    │ ← 날짜를 누르면 앱 오늘 화면, +를 누르면 새 일정
├──────────────────────────────────┤
│ 오늘                              │
│ ▌종일   개천절 대체휴일           │ ← 휴일은 빨간 글자
│ ▌13:30  기전팀 보고  · 본사 3층   │ ← 캘린더 색 막대, 일정을 누르면 상세
│ ▌19:00  동창회                    │
│ 내일 (화)                         │
│ ▌10:00  치과                      │
│ …                                 │
├──────────────────────────────────┤
│ ● 연동 3분 전 · 문제 없음         │ ← 연동 상태 줄(연결했을 때만 보임)
└──────────────────────────────────┘
```

- **보여 줄 범위:** 오늘부터 14일. 일정이 없는 날은 건너뛰고, 지난 일정(오늘 끝난 것)은 흐리게 보이다 다음 갱신 때 빠진다.
- **크기별 구성:**
  - 3×2: 머리글과 일정 3개
  - 4×2 이상: 위치 표시
  - 4×4 이상: 연동 상태 줄 + 스크롤 목록
- **빈 상태:** "앞으로 2주 동안 일정이 없습니다" + [새 일정].

### W2. 월 달력 — 2차 (기본 4×4, 크기 4×3 ~ 5×5)

```
┌──────────────────────────────────┐
│ ‹  2026년 10월  ›         [+]    │ ← 화살표로 달을 넘김(위젯 안에서)
│ 일 월 화 수 목 금 토              │
│     ·  ·  1  2  3  4              │
│  5  6  7  8 ⑨ 10 11               │ ← 오늘은 Clay 원, 일정은 점(최대 3개)
│ …                                 │
├──────────────────────────────────┤
│ 오늘 13:30 기전팀 보고 외 2개     │ ← 5×5 이상이면 선택한 날 일정 줄(삼성 위젯에 없는 것)
└──────────────────────────────────┘
```

- 일요일·공휴일은 빨간 숫자로 보인다. 음력 1일·15일 표시는 앱 설정을 따른다.
- 날짜를 누르면 앱이 그 날짜의 월 보기로 열린다.

### W3. 작은 위젯 — 3차 (2×1 / 2×2)

- **다음 일정:** "13:30 기전팀 보고 · 25분 후". 일정이 없으면 날짜와 음력만 보인다.
- 나중에 D-day 기능이 생기면 같은 위젯에서 "시험 D-12"를 고를 수 있게 한다.

## 4. 데이터 규칙 (앱과 같은 결과)

1. **읽기:** `AndroidCalendarStore.occurrences()`로 읽는다. 위젯은 앱 프로세스가 없어도 동작한다.
2. **어떤 캘린더를 보일지:** 앱 서랍의 표시 설정(`AppSettings.isShown`)을 그대로 따른다. 그러면 위젯마다 따로 정할 필요가 없다.
3. **연동된 두 일정은 하나로:** 삼성 캘린더 쪽만 보인다. 컨트롤러의 `shownOf` 규칙을 공용 함수로 꺼내 앱과 위젯이 같이 쓴다.
4. **휴일:** `KoreanHolidays`에 켜 둔 공휴일 캘린더를 더한다. 앱의 `isHoliday`와 같은 계산이다.
5. **시간 표기:** 휴대폰의 12/24시간 설정을 따른다.
6. **연동 상태 줄:** `BridgeEngine`에 저장된 마지막 보고를 읽는다. 표시는 다음 중 하나다.
   - "연동 3분 전 · 문제 없음"
   - 실패, 삭제 대기, 중복, 동기화 꺼짐일 때는 빨간 점과 "확인 필요"
   - 이 줄을 누르면 앱의 연동 시트가 열린다.

## 5. 갱신 시점

| 계기 | 방법 |
|---|---|
| 캘린더가 바뀜(삼성 캘린더 편집, Google 동기화 도착, 연동 결과) | 이미 있는 `BridgeWorker`의 변경 감지 작업 끝에 위젯을 갱신한다. 연동이 꺼져 있어도 위젯이 있으면 같은 감지 작업을 건다 |
| OLO에서 저장·삭제 | 컨트롤러 `reload()` 뒤 위젯을 갱신한다 |
| 날짜가 바뀜(자정), 시간대·시각 변경 | `DATE_CHANGED` / `TIMEZONE_CHANGED` / `TIME_SET` 수신 + 자정 작업 |
| 일정이 끝남(목록에서 빼기) | 다음 일정 종료 시각에 한 번 갱신(WorkManager 한 번 실행). 배터리를 위해 15분보다 잦게 하지 않는다 |
| 안전망 | `updatePeriodMillis` 30분 |

## 6. 구현 방식

- **기술:**
  - Jetpack **Glance 1.1.1** (안정판). Compose 문법으로 위젯을 작성한다.
  - `androidMain`에만 둔다. iOS는 WidgetKit(SwiftUI)으로 따로 만들고, 그 시점은 iOS 앱 착수 때로 미룬다.
- **크기:** `SizeMode.Responsive`로 3×2, 4×2, 4×4, 5×5 구성을 미리 정한다. 폴드를 펼쳤을 때도 같은 규칙을 쓴다.
- **누를 때:**
  - `actionStartActivity`로 MainActivity를 연다. 열 화면은 extra로 넘긴다: 날짜, 일정 id, "새 일정", "연동 시트".
  - 앱에 이 진입점(딥링크)을 새로 추가한다.
- **월 넘기기:** `actionRunCallback`으로 위젯 상태(보는 달)만 바꾸고 다시 그린다. 앱은 열지 않는다.
- **디자인:**
  - OLO 토큰(Clay, 캘린더 색, 휴일 빨강)을 쓰고, 라이트/다크는 시스템을 따른다.
  - 배경 투명도는 3단계(불투명 / 반투명 / 투명)로 둔다. 2차에 위젯 설정 화면을 만들 때 넣는다.
- **제약:**
  - Glance의 Row/Column은 자식 10개까지다. 월 격자(7×6)는 줄 단위로 나누면 들어간다.
  - 원격 뷰라서 애니메이션은 쓰지 않는다.
- **권한:** 캘린더 권한이 없으면 위젯에 "OLO를 열어 캘린더 권한을 허용해 주세요"를 띄운다. 누르면 앱이 열린다.

## 8. 결정 대기

- **A.** 1차 범위: 목록 위젯만(권장, 0.12.0) vs 목록과 월 위젯을 한 번에
- **B.** 표시할 캘린더: 앱 표시 설정을 따른다(권장) vs 위젯마다 따로 고른다
- **C.** 연동 상태 줄: 늘 보인다(권장, 정상이면 회색 한 줄) vs 문제가 있을 때만 보인다
- **D.** 목록 기간: 14일(권장) vs 7일 vs 30일

## 9. 0.12.0 적용 내역

- **결정 (2026-10-19, "진행"):** A 목록 위젯만 · B 앱 표시 설정을 따름 · C 연동 상태 줄은 늘 보임 · D 14일 (모두 권장안)
- **공용 로직 (`model/Agenda.kt`):**
  - 컨트롤러에 있던 표시 규칙을 `shownOccurrences`로 꺼냈다. 숨긴 캘린더 제외, 연동된 일정은 한 번만, OLO 색 적용을 맡는다.
  - 휴일 계산은 `holidayNamesOn`으로 꺼냈다.
  - `widgetAgenda`가 위젯 목록을 만든다.
    - 오늘은 늘 맨 위에 둔다.
    - 여러 날 일정은 처음 보이는 날에 한 번만 넣는다.
    - 오늘 끝난 일정은 뺀다.
    - 공휴일 캘린더의 일정은 휴일로 표시한다.
  - 연동 상태 줄은 `store/BridgeEngine.kt`의 `bridgeStatusLine`이 만든다. 시간 표시는 `model/BridgeLog.kt`의 `agoText`를 쓴다.
- **위젯 (`androidMain/AgendaWidget.kt`, Glance 1.1.1):**
  - 크기별 구성은 다음과 같다.
    - 180×110dp: 일정 4줄
    - 250dp 이상: 장소까지 표시
    - 220dp 이상 높이: 스크롤 목록과 연동 상태 줄
  - 라이트/다크 OLO 색을 쓴다.
  - 권한이 없거나 일정이 없을 때 안내 문구를 띄운다.
- **누를 때:** `MainActivity`가 `ACTION_OPEN`과 extra를 `OpenRequest`로 바꾼다(Day / Event / NewEvent / Bridge). 그러면 `CalendarScreen`이 그 날짜, 상세, 새 일정, 연동 시트를 연다. 앱이 이미 열려 있으면 `singleTop` + `onNewIntent`로 받는다.
- **갱신:**
  - 캘린더가 바뀌면 `BridgeWorker`의 변경 감지 끝에서 위젯을 다시 그린다. 연동이 꺼져 있어도 위젯이 있으면 감지를 유지한다.
  - OLO에서 저장, 삭제, 표시 설정 변경, 연동을 하면 컨트롤러의 `onChanged`가 `Widgets.refresh`를 부른다.
  - 자정이나 오늘 다음 일정의 종료 시각에는 `Widgets.scheduleTick`이 다시 그린다. 간격은 최소 5분이다.
  - 시간대 변경과 시각 직접 설정은 `WidgetClockReceiver`가 받는다.
  - 안전망으로 30분 주기 갱신을 둔다.
- **테스트:** commonTest `AgendaTest` 4건. 오늘 고정·끝난 일정 제외, 긴 일정 한 번·빈 날 생략·14일 범위, 휴일 캘린더·연동 일정 합치기, 연동 상태 줄을 검증한다.
- **실기기 확인 필요:** 위젯 화면은 데스크톱 스크린샷으로 그릴 수 없다. 갤럭시에서 크기별 모양, 다크 모드, 탭 이동을 확인해야 한다.

## 10. 0.12.1 적용 내역 (W2 월 달력)

- **공용 로직 (`model/MonthWidget.kt`):** `monthWidgetWeeks`가 월 격자를 만든다.
  - 격자는 앱 월 보기와 같은 `monthGrid`를 쓴다. 그래서 4~6주이고, 앱에서 정한 주 시작 요일을 따른다.
  - 날짜마다 일정 점을 최대 3개 찍는다. 종일 일정의 점이 먼저 오고, 4번째부터는 `more`로 센다.
  - 일요일과 휴일은 빨간 숫자다. 공휴일 캘린더의 일정은 점을 찍지 않고 숫자만 빨갛게 한다.
  - 음력 1일·15일 라벨은 앱의 음력 설정을 따른다.
- **위젯 (`androidMain/MonthWidget.kt`):** 크기별 구성은 다음과 같다.
  - 4×3 (250×160dp): 숫자와 점
  - 4×4 (250×250dp): 더 큰 숫자와 오늘 원
  - 5×5 (300×330dp): 음력 라벨 + 오늘 남은 일정 2줄("외 N개") + 연동 상태 줄
- **달 넘기기:**
  - ‹ › 버튼은 `MonthStep`(ActionCallback)이 위젯별 상태를 바꾼다. 상태는 Glance Preferences의 `monthOffset`, `turnedOn`이다.
  - 다시 그릴 때는 바뀐 달만 새로 읽는다. 앱은 열지 않는다.
  - 다른 달을 보는 중에 제목을 누르면 이번 달로 돌아온다. 이번 달에서 누르면 앱이 열린다.
  - 다음 날이 되면 이번 달부터 다시 보인다.
- **누를 때:** 날짜 칸을 누르면 앱이 그 날짜로 열린다. +는 새 일정, 일정 줄은 그 일정 상세, 상태 줄은 연동 시트를 연다.
- **공통 정리:**
  - 두 위젯은 `readWidgetSource`(설정·표시 일정·휴일 캘린더·연동 상태 읽기)와 색 토큰을 함께 쓴다.
  - `Widgets.updateAll`, `Widgets.any`, `Widgets.anyPlaced`가 두 위젯을 함께 다룬다.
  - 마지막 위젯이 빠지면 일정 갱신 작업을 멈춘다. 연동이 꺼져 있으면 변경 감지 작업도 멈춘다.
- **테스트:** commonTest `MonthWidgetTest`가 다음을 검증한다: 5주 격자, 점 3개 + more, 휴일 캘린더, 오늘 표시, 음력 라벨.
- **실기기 확인 필요:** 크기별 칸 모양, 다크 모드, ‹ › 반응 속도(목표 1초 안).
